# Technical Daily Report

## 适用场景

仅在技术团队需要依据提交、任务、测试、发布或故障事实生成研发日报、技术日报时使用。

## 所需事实

确认日期、项目/服务、代码或配置变化、任务状态、测试结果、发布事实、事故影响、阻塞、负责人和下一动作。缺少提交、测试或监控证据时标为“待确认”。

## 输出结构

1. 今日技术状态；2. 重要变更与影响；3. 测试/发布证据；4. 风险与阻塞；5. 下一步和负责人；6. 待确认事项。

## 渐进披露

先给总体状态、最重要变更、阻塞和下一动作；需要工程复核时再展开提交/任务编号、测试矩阵、故障时间线和技术细节。

## 最终检查

区分已合并、已部署、已验证和仅计划；不把提交数量当成果，不虚构覆盖率、完成率、影响范围或负责人。
