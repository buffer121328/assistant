# Technical Document Layout

## 适用场景

仅在用户需要整理设计文档、接口文档、技术方案、故障复盘或运维说明的结构与排版时使用。

## 所需事实

确认文档类型、受众、目标、系统边界、版本、事实材料、决策、接口/代码/表格、风险和维护人。缺失内容标为“待确认”。

## 输出结构

采用标题、摘要、背景/范围、架构或流程、关键细节、证据/示例、决策、风险、操作步骤和后续行动的清晰层级；代码、表格和告警使用独立区块。

## 渐进披露

先给摘要、文档目录和关键决策；结构确认后再填充技术细节、代码示例、表格和附录。长文优先让每一节开头表达结论。

## 最终检查

检查术语、版本、标题层级、代码语言和表格口径一致；不承诺编辑既有文件、保留源版式或生成未经授权的外部链接。
